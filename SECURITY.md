# Security / Sécurité

## English

Do not disclose a vulnerability in a public issue, discussion, log, or pull request. Use the private
security reporting channel configured for the official organization. Until that channel is
available, contact the project owner directly and include no secret, credential, token, personal
data, or production extract in the report.

Provide a concise impact description, affected component and version, reproduction conditions, and a
safe proof of concept when possible. Maintainers will acknowledge the report privately, assess
severity, coordinate remediation, and publish an advisory when disclosure is safe.

Supported versions will be listed with the first prerelease. Only verifiable official artifacts may
receive an official security update. Never weaken a security control merely to preserve an
undocumented behavior.

## Français

Ne publiez pas une vulnérabilité dans une issue publique. Utilisez le canal privé de signalement de
sécurité qui sera configuré sur l'organisation officielle. Dans l'attente, contactez directement le
propriétaire du projet sans joindre de secret dans un ticket ou un journal.

Les versions prises en charge seront listées à la première préversion. Seuls les artefacts officiels
signés peuvent recevoir un correctif de sécurité officiel.
