# Contributing / Contribuer

## English

Thank you for contributing to Compendlore.

### Before starting

1. Open or reference a request describing the problem and expected observable result.
2. Work in a short-lived branch created from `main`.
3. Never commit secrets, personal data, runtime data, generated builds, or local configuration.
4. Add or update tests and the useful repository documentation.
5. Run `npm run ci` before submitting the change.

### Review

Changes are integrated through pull requests. The branch must be current, all automated checks must
pass, and at least one maintainer must approve it. Security, licensing, release, Core, and
public-contract changes may require two approvals.

### Documentation

Repository Markdown must be necessary to use, secure, license, or contribute to the project. It must
present English first and French second. Architecture, planning, audits, and long-form project
documentation belong in the workspace documentation tree, not in this repository. Community policies
such as the code of conduct, governance, and trademark rules remain in the repository.

### Contribution origin

By submitting a contribution, you certify that you authored it or hold the necessary rights and
agree that it may be used under the project license. The project CLA remains a draft and must not be
activated before legal review.

## Français

Merci de contribuer à Compendlore.

### Avant de commencer

1. Ouvrir ou rattacher une demande décrivant le problème et le résultat attendu.
2. Travailler dans une branche courte issue de `main`.
3. Ne jamais ajouter de secret, donnée personnelle ou donnée runtime.
4. Ajouter ou adapter les tests et la documentation.
5. Exécuter `npm run ci` avant de proposer la contribution.

### Revue

Les changements sont intégrés par pull request. La branche doit être à jour, les contrôles
automatiques doivent réussir et au moins un mainteneur doit approuver. Les zones sensibles peuvent
exiger deux approbations.

### Documentation

Les fichiers Markdown du dépôt doivent être nécessaires à l’utilisation, à la sécurité, à la licence
ou à la contribution au projet. Ils présentent d’abord l’anglais, puis le français. L’architecture,
la planification, les audits et la documentation longue du projet appartiennent à l’arborescence
documentaire du workspace et non à ce dépôt. Les politiques communautaires telles que le code de
conduite, la gouvernance et les règles de marque restent dans le dépôt.

### Origine des contributions

En soumettant une contribution, vous certifiez en être l'auteur ou disposer des droits nécessaires
et acceptez que celle-ci soit utilisée sous la licence du projet. Le CLA fourni dans ce dépôt devra
être validé avant toute publication communautaire ; sa validation juridique reste un prérequis
explicite.
